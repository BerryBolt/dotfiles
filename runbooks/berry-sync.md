# Repository synchronization

Run `berry-sync` manually. Apply registers the Hermes job `dotfiles-berry-sync` every five minutes with `no_agent=True`. The job runs the managed `~/.hermes/scripts/berry-sync.sh` wrapper. Hermes requires scripts inside that directory. It starts no model turn and keeps delivery local. Registration preserves other jobs and an existing job's paused state. Duplicate names stop registration for manual resolution.

The command discovers dotfiles through `chezmoi source-path` and uses `~/brain` for the workspace. Each repository needs an attached branch with an upstream. Dirty, detached, ahead, and diverged checkouts defer independently. Missing or inaccessible checkouts fail independently. The command never stashes, resets, commits, or pushes. Manual runs exit nonzero when incomplete. Scheduled runs treat routine deferrals as success and report their reason on stderr; actual failures exit nonzero. Git and apply output stays suppressed because errors and rendered templates may contain credentials. Inspect the checkout locally to diagnose a failure, and avoid printing secret-bearing diffs into logs.

A clean checkout advances only by fast-forward. Dotfiles then runs `chezmoi-with-op --no-tty --force=false apply` with closed stdin. Chezmoi refuses conflicting edits to targets it has previously written. A newly managed path has no recorded state and may replace existing content without prompting. Before publishing a new managed path, inspect its destination and preserve existing content. Record those edits in source before retrying. Apply can make partial progress before it fails. Its last successful SHA stays in `$XDG_STATE_HOME/berry-sync/applied-sha`, or `~/.local/state/berry-sync/applied-sha`. A missing marker triggers an apply. Scheduled attempts at the same SHA run at most hourly after a failed or interrupted apply. A new SHA or manual run retries immediately. A successful marker suppresses further applies at that SHA, so use a manual chezmoi apply for secret rotation or target repairs without a source change.

An advisory file lock prevents overlapping manual and scheduled runs. The installer holds the same lock while it updates the source, applies files, and creates the workspace. Other editors and manual chezmoi commands do not honor this lock. Avoid changing branches or applying manually during a sync. Python loads the command before apply replaces its installed file. The next invocation loads the replacement. Existing script 60 queues graceful gateway restarts in a separate systemd unit. A queued restart does not prove the gateway loaded its configuration. If interruption occurs before the marker write, the next run retries. Hermes' script timeout also limits execution, so a slow package install can require manual apply.

Registration does not need the brain checkout. A fresh install registers the job during its first apply, then clones the brain through the existing installer. Ticks defer until the installer releases the lock after the clone and link apply. Pinned installations remain detached and require an operator to select a tracking branch before automatic updates can run.

## Acceptance

Local syntax and ShellCheck checks do not prove the deployed workflow. On an authorized disposable Omarchy account, run the existing acceptance scripts against the published candidate. Confirm one job after two applies, unchanged unrelated jobs, a manual run, and a scheduled run. Exercise clean fast-forwards, dirty and detached skips, ahead and diverged branches, a target conflict, an apply failure followed by retry at the same SHA, overlapping runs, and a script update. Confirm the gateway returns after a configuration change and inspect its effective configuration. Fresh install must also prove the post-apply brain clone works.

A stopped gateway cannot run the schedule. Recover it manually, then run `berry-sync` to fetch a corrective commit. Include a Hermes pin upgrade during a scheduled apply in VM acceptance.
